# Where account and payment logic lives

Use the method names below to jump to a feature in your IDE. The React form collects input, the API client sends it, the NestJS controller checks access and routes the request, and the backend service owns the business rules.

## Admin Dashboard and staff accounts

| Action | Backend method | What it does |
| --- | --- | --- |
| Change my password in **My Profile** | `StaffProfileService.changePassword()` in [staff-profile.service.ts](../backend/src/users/staff-profile.service.ts) | Verifies the current password, checks the replacement and its confirmation, and hashes the new password. The shared `write()` method saves the change, invalidates sessions, and records the audit event in one transaction. |
| Change my sign-in email in **My Profile** | `StaffProfileService.changeEmail()` in [staff-profile.service.ts](../backend/src/users/staff-profile.service.ts) | Verifies the current password, normalizes the new address, and saves it immediately. A successful change requires a fresh sign-in. |
| Reset another staff member’s password | `UsersService.resetDefaultPassword()` in [users.service.ts](../backend/src/users/users.service.ts) | Applies the role and account restrictions, resets the target to the configured staff default password, revokes sessions, and requires the target to choose a replacement. |
| Choose a new password after a staff reset | `StaffPasswordService.changeTemporaryPassword()` in [staff-password.service.ts](../backend/src/auth/staff-password.service.ts) | Checks the temporary password and completes the required replacement. The same service handles invitation setup separately through `setupPassword()`. |

**Follow the profile form.** Start at the form, then follow its submit handler and API client. The controller receives `POST /api/staff/profile/password` or `POST /api/staff/profile/email`. [My Profile form](../frontend/admin-web/src/features/profile/pages/MyProfile.jsx) · [Submit handler](../frontend/admin-web/src/features/profile/hooks/useStaffProfile.js) · [API client](../frontend/admin-web/src/features/profile/services/staffProfileApi.js) · [Profile controller](../backend/src/users/staff-profile.controller.ts)

**Follow an administrator-initiated reset.** The staff account editor starts the reset through `POST /api/staff/users/:id/reset-password`. The affected staff member later submits `POST /api/auth/staff/change-temporary-password`. [Reset control](../frontend/admin-web/src/features/users/components/StaffPasswordReset.jsx) · [Users controller](../backend/src/users/users.controller.ts) · [Staff replacement page](../frontend/admin-web/src/features/auth/pages/StaffPassword.jsx) · [Staff password controller](../backend/src/auth/staff-password.controller.ts)

## Guest Website

All three guest flows use [guestCredentialsApi.js](../frontend/guest-web/src/features/auth/services/guestCredentialsApi.js), [GuestCredentialsController](../backend/src/auth/guest-credentials.controller.ts), and [GuestCredentialsService](../backend/src/auth/guest-credentials.service.ts). Each endpoint below is a POST under `/api/auth/guest/`.

| Action | Guest screen | Endpoint and service method |
| --- | --- | --- |
| Change a known password | [My Account](../frontend/guest-web/src/features/auth/pages/AccountSecurity.jsx) | `password` → `changePassword()`. Checks the current password and the replacement, then saves its hash and revokes existing sessions. |
| Reset a forgotten password | [Forgot password](../frontend/guest-web/src/features/auth/pages/ForgotPassword.jsx) → [Reset form](../frontend/guest-web/src/features/auth/pages/GuestCredentialLink.jsx) | `forgot-password` → `forgotPassword()` issues a recovery link for an eligible guest. `reset-password` → `resetPassword()` claims the link and saves the replacement password. The public request returns the same acknowledgment for all email addresses. |
| Change sign-in email | [My Account](../frontend/guest-web/src/features/auth/pages/AccountSecurity.jsx) → [Confirmation form](../frontend/guest-web/src/features/auth/pages/GuestCredentialLink.jsx) | `email` → `requestEmailChange()` checks the current password and sends a link to the new address. `confirm-email` → `confirmEmailChange()` switches the sign-in address only after confirmation. |

Inside the guest service, `issue()` creates a purpose-specific link, `consume()` claims it once, and `apply()` updates credentials and revokes sessions. Reset and email-change links expire after 30 minutes. For password hashing, open [PasswordService](../backend/src/auth/password.service.ts). For link construction and SMTP delivery, open [EmailService](../backend/src/auth/email.service.ts).

## Payments

| If you are tracing… | Start here | What to follow |
| --- | --- | --- |
| A guest starting online payment during booking | [Guest booking API](../frontend/guest-web/src/features/checkout/services/guestBookingApi.js) → [Guest bookings controller](../backend/src/reservations/guest-booking/guest-bookings.controller.ts) | `startGuestBookingCheckout()` leads to `CheckoutService.startForUser()`, which handles the checkout attempt. The provider adapter communicates with PayMongo. [Checkout service](../backend/src/payments/checkout/checkout.service.ts) · [PayMongo adapter](../backend/src/payments/paymongo/paymongo.adapter.ts) |
| A guest paying or retrying from an existing reservation | [Booking payments API](../frontend/guest-web/src/features/payments/services/bookingPaymentsApi.js) → [Payments controller](../backend/src/payments/checkout/payments.controller.ts) | `startReservationCheckout()` and `retryReservationCheckout()` call the reservation checkout routes. Follow `startForUser()` or `retryForUser()` in the [checkout service](../backend/src/payments/checkout/checkout.service.ts). |
| How an online payment becomes confirmed | [Webhook controller](../backend/src/payments/paymongo/webhooks.controller.ts) → [Webhook service](../backend/src/payments/paymongo/paymongo-webhook.service.ts) | `POST /api/webhooks/paymongo` passes the original request body and signature to `handle()`. Follow this path for signature verification, duplicate provider events, and payment updates. [Signature verification](../backend/src/payments/paymongo/paymongo-webhook.signature.ts) |
| What the guest sees after returning from PayMongo | [Payment return page](../frontend/guest-web/src/features/payments/pages/PaymentReturn.jsx) → [Return summary hook](../frontend/guest-web/src/features/payments/hooks/usePaymentReturnSummary.js) | The page reads the backend payment summary. A browser redirect alone does not mark a reservation paid. [Payment summary service](../backend/src/payments/summary/payment-summary.service.ts) |
| Staff collecting payment at the property | [Collection form](../frontend/admin-web/src/features/payments/components/PropertyCollection.jsx) → [Collection controller](../backend/src/payments/collections/pay-at-property.controller.ts) | `POST /api/payments/reservations/:reservationId/pay-at-property` calls `PayAtPropertyService.record()`. Start there for collection validation and database writes. [Collection service](../backend/src/payments/collections/pay-at-property.service.ts) |
| Staff reviewing a payment, issuing a refund, or reconciling provider records | [Staff payments controller](../backend/src/payments/summary/staff-payments.controller.ts) · [Refund controller](../backend/src/payments/refunds/refunds.controller.ts) · [Reconciliation controller](../backend/src/payments/reconciliation/payment-reconciliation.controller.ts) | List and detail reads use the [staff payments service](../backend/src/payments/summary/staff-payments.service.ts). Super Admin refund creation uses `RefundsService.create()` in the [refund service](../backend/src/payments/refunds/refunds.service.ts). Provider reconciliation uses `payment()` and `refund()` in the [reconciliation service](../backend/src/payments/reconciliation/payment-reconciliation.service.ts). |
